# M4.5 — Integration Test Suite (Property Strategy)

This milestone exercises M4's property strategy against the in-repo orders API. The broken endpoint — deliberately seeded in M2.5 — is the primary target: property testing must find its schema violation automatically, with no hand-written assertions.

From this point forward the integration suite has three layers running in CI: table tests (M2.5), replay smoke tests (M3.5), and property tests (M4.5).

---

## Overview

M4.5 delivers three things:

1. **Property test config** — a `backendtest-property.yaml` and invariant configuration for the orders API that targets the broken endpoint and the create endpoint
2. **Verification that the broken endpoint is found automatically** — `bt run --strategy property` must report a `response_matches_schema` failure on `/orders/{id}/broken` with a meaningful schema violation, without any hand-written case
3. **CI integration** — property tests run as part of the GitHub Actions workflow, with seed logging, artifact capture, and failure reporting

**Exit criterion:** `bt run --strategy property` finds the broken endpoint's schema violation automatically. The failure report includes the schema violation path, the shrunk input, and the artifact path. CI captures the seed so the run can be reproduced.

## Step 2 — Property test configuration

### Spec

Create `examples/orders-api/bt/backendtest-property.yaml`:

```yaml
version: 1

target:
  name: orders-api
  base_url: http://localhost:8080
  schema: ../openapi.yaml

strategies:
  - type: property
    checks: 200       # number of Rapid test cases per operation
    seed: 0           # 0 means random; CI logs the seed used for reproduction
    invariants:
      - no_5xx
      - response_matches_schema
      - idempotency_key_prevents_duplicates
    operations:
      # The broken endpoint: property testing should find the schema violation
      # automatically within 200 checks. No seed is fixed here — the whole
      # point is that the tool finds the bug on its own.
      - operation_id: GetOrderBroken
        checks: 50    # 50 is enough; the broken endpoint fails ~50% of calls

      # The create endpoint: generates valid-but-boundary inputs to check
      # the response schema and idempotency behaviour.
      - operation_id: CreateOrder
        checks: 200

report:
  formats: [console, json]
  output_dir: ./.bt/artifacts

safety:
  profile: safe
```

## Step 3 — Verify the broken endpoint is found automatically

The broken endpoint returns an incomplete response on odd-numbered calls. Property testing with `response_matches_schema` must find this without any assertion written by hand.

### Spec

The property run against `GetOrderBroken` must:
- Find at least one `response_matches_schema` failure within 50 checks
- Report the violation at one or more of the paths: `$.amount`, `$.currency`, `$.status`
- Write an artifact bundle for the failure
- Log the seed used so the failure can be reproduced

This is verified in CI by inspecting the JSON output of the property run.

### Local verification script

`examples/orders-api/bt/scripts/verify-property-finds-broken.sh`:

```bash
#!/usr/bin/env bash
# Verifies that bt property testing finds the broken endpoint's schema violation.
# Expects the orders API to be running on localhost:8080.
set -euo pipefail

ARTIFACT_DIR="examples/orders-api/bt/.bt/artifacts"
REPORT_FILE="examples/orders-api/bt/.bt/reports/property-run.json"

echo "=== Running property tests ==="
mkdir -p "$(dirname "$REPORT_FILE")"
# Allow failure — we expect the broken endpoint to fail.
./bt run \
  --config examples/orders-api/bt/backendtest-property.yaml \
  --strategy property \
  --output json \
  --output-file "$REPORT_FILE" \
  || true

echo ""
echo "=== Checking report for response_matches_schema failure ==="
if ! command -v jq &>/dev/null; then
  echo "jq not available — skipping structured report check"
  exit 0
fi

SCHEMA_FAILURES=$(jq '[.results[] | select(.failures[]?.invariant == "response_matches_schema")] | length' "$REPORT_FILE" 2>/dev/null || echo "0")
if [ "$SCHEMA_FAILURES" -eq 0 ]; then
  echo "FAIL: property testing did not find a response_matches_schema failure on the broken endpoint"
  exit 1
fi
echo "OK: found $SCHEMA_FAILURES result(s) with response_matches_schema violations"

echo ""
echo "=== Checking violation paths are meaningful ==="
PATHS=$(jq -r '[.results[].failures[]? | select(.invariant == "response_matches_schema") | .path] | unique | .[]' "$REPORT_FILE" 2>/dev/null || true)
if [ -z "$PATHS" ]; then
  echo "FAIL: schema violations have no path information"
  exit 1
fi
echo "Violation paths found:"
echo "$PATHS"

echo ""
echo "=== Checking artifact was written ==="
ARTIFACT_COUNT=$(ls "$ARTIFACT_DIR"/*.json 2>/dev/null | wc -l || echo "0")
if [ "$ARTIFACT_COUNT" -eq 0 ]; then
  echo "FAIL: no artifact written for property test failure"
  exit 1
fi
echo "OK: $ARTIFACT_COUNT artifact(s) found"

echo ""
echo "=== Checking seed is present in report ==="
SEED=$(jq '.results[] | select(.strategy_kind == "property") | .seed' "$REPORT_FILE" 2>/dev/null | head -1 || echo "")
if [ -z "$SEED" ] || [ "$SEED" = "null" ]; then
  echo "FAIL: seed not found in property run report"
  exit 1
fi
echo "OK: seed logged as $SEED"

echo ""
echo "=== All property integration checks passed ==="
```

### Tests for the verification script itself

Rather than shell tests, the verification is done at the Go level as a CI integration test. Add `examples/orders-api/integration/property_test.go`:

```go
//go:build integration
// +build integration

package integration_test

import (
	"encoding/json"
	"os"
	"os/exec"
	"testing"
)

// propertyReport matches the JSON output format from bt run --output json.
type propertyReport struct {
	Results []propertyResult `json:"results"`
}

type propertyResult struct {
	CaseID       string    `json:"case_id"`
	StrategyKind string    `json:"strategy_kind"`
	Seed         int64     `json:"seed"`
	CasesRun     int       `json:"cases_run"`
	ShrinkCount  int       `json:"shrink_count"`
	Failures     []failure `json:"failures"`
	ArtifactPath string    `json:"artifact_path"`
}

type failure struct {
	Invariant string `json:"invariant"`
	Message   string `json:"message"`
	Path      string `json:"path"`
	Expected  string `json:"expected"`
	Actual    string `json:"actual"`
}

func runPropertyTests(t *testing.T) propertyReport {
	t.Helper()

	reportFile := t.TempDir() + "/property-report.json"

	cmd := exec.Command(
		"../../../bt",
		"run",
		"--config", "bt/backendtest-property.yaml",
		"--strategy", "property",
		"--output", "json",
		"--output-file", reportFile,
	)
	cmd.Dir = "."
	// Allow non-zero exit — property failures exit 1.
	cmd.Run()

	data, err := os.ReadFile(reportFile)
	if err != nil {
		t.Fatalf("cannot read property report: %v", err)
	}

	var report propertyReport
	if err := json.Unmarshal(data, &report); err != nil {
		t.Fatalf("cannot parse property report JSON: %v\nraw: %s", err, data)
	}
	return report
}

func TestPropertyIntegration_BrokenEndpoint_FoundAutomatically(t *testing.T) {
	report := runPropertyTests(t)

	found := false
	for _, r := range report.Results {
		if r.CaseID == "GetOrderBroken" || r.StrategyKind == "property" {
			for _, f := range r.Failures {
				if f.Invariant == "response_matches_schema" {
					found = true
				}
			}
		}
	}

	if !found {
		t.Error("expected property testing to find a response_matches_schema failure on the broken endpoint automatically")
	}
}

func TestPropertyIntegration_BrokenEndpoint_ViolationHasPath(t *testing.T) {
	report := runPropertyTests(t)

	for _, r := range report.Results {
		for _, f := range r.Failures {
			if f.Invariant == "response_matches_schema" {
				if f.Path == "" {
					t.Errorf("schema violation has empty path — expected a JSON path like '$.amount': %+v", f)
				}
				return // found one with a path, test passes
			}
		}
	}
	t.Error("no response_matches_schema failures found to check path on")
}

func TestPropertyIntegration_BrokenEndpoint_ViolationHasExpectedAndActual(t *testing.T) {
	report := runPropertyTests(t)

	for _, r := range report.Results {
		for _, f := range r.Failures {
			if f.Invariant == "response_matches_schema" {
				if f.Expected == "" {
					t.Errorf("schema violation at %q has empty Expected field", f.Path)
				}
				return
			}
		}
	}
	t.Error("no response_matches_schema failures found to check Expected/Actual on")
}

func TestPropertyIntegration_BrokenEndpoint_ArtifactIsWritten(t *testing.T) {
	report := runPropertyTests(t)

	for _, r := range report.Results {
		if len(r.Failures) > 0 && r.ArtifactPath != "" {
			if _, err := os.Stat(r.ArtifactPath); os.IsNotExist(err) {
				t.Errorf("artifact path %q referenced in report but file does not exist", r.ArtifactPath)
			}
			return
		}
	}
	t.Error("no failing result with an artifact path was found in the report")
}

func TestPropertyIntegration_PropertyResults_SeedIsPresent(t *testing.T) {
	report := runPropertyTests(t)

	for _, r := range report.Results {
		if r.StrategyKind == "property" {
			if r.Seed == 0 {
				t.Errorf("property result %q has seed 0 — seed must be set even for random runs", r.CaseID)
			}
		}
	}
}

func TestPropertyIntegration_PropertyResults_CasesRunIsPositive(t *testing.T) {
	report := runPropertyTests(t)

	for _, r := range report.Results {
		if r.StrategyKind == "property" {
			if r.CasesRun <= 0 {
				t.Errorf("property result %q has CasesRun=%d — expected > 0", r.CaseID, r.CasesRun)
			}
		}
	}
}

func TestPropertyIntegration_BrokenEndpoint_ShrinkCountIsPositive(t *testing.T) {
	report := runPropertyTests(t)

	for _, r := range report.Results {
		for _, f := range r.Failures {
			if f.Invariant == "response_matches_schema" {
				if r.ShrinkCount <= 0 {
					t.Errorf("expected shrink count > 0 for a found failure, got %d", r.ShrinkCount)
				}
				return
			}
		}
	}
}

func TestPropertyIntegration_PassingRun_ReplaySeed(t *testing.T) {
	// After finding the failure, rerun with the same seed — must find the same failure.
	report := runPropertyTests(t)

	var seed int64
	for _, r := range report.Results {
		if len(r.Failures) > 0 && r.Seed != 0 {
			seed = r.Seed
			break
		}
	}
	if seed == 0 {
		t.Skip("no failing result with a seed — skipping replay determinism check")
	}

	// Run again with the captured seed.
	reportFile := t.TempDir() + "/replay-report.json"
	cmd := exec.Command(
		"../../../bt",
		"run",
		"--config", "bt/backendtest-property.yaml",
		"--strategy", "property",
		"--seed", fmt.Sprintf("%d", seed),
		"--output", "json",
		"--output-file", reportFile,
	)
	cmd.Dir = "."
	cmd.Run()

	data, err := os.ReadFile(reportFile)
	if err != nil {
		t.Fatalf("cannot read replay report: %v", err)
	}

	var replay propertyReport
	if err := json.Unmarshal(data, &replay); err != nil {
		t.Fatalf("cannot parse replay report: %v", err)
	}

	// The seeded replay must also find a failure.
	foundFailure := false
	for _, r := range replay.Results {
		if len(r.Failures) > 0 {
			foundFailure = true
		}
	}
	if !foundFailure {
		t.Error("seeded replay did not reproduce the failure found in the initial run")
	}
}
```

## Step 4 — Update CI workflow

Update `.github/workflows/ci.yml` to add property test steps after the M3.5 replay steps:

```yaml
      # M4.5 — property strategy integration tests
      - name: Property tests (broken endpoint + create endpoint)
        # Allow failure — the broken endpoint is expected to fail.
        # The important thing is that the report is produced.
        run: |
          ./bt run \
            --config examples/orders-api/bt/backendtest-property.yaml \
            --strategy property \
            --output json \
            --output-file examples/orders-api/bt/.bt/reports/property-run.json \
          || true

      - name: Verify property tests found broken endpoint
        run: |
          REPORT="examples/orders-api/bt/.bt/reports/property-run.json"
          if [ ! -f "$REPORT" ]; then
            echo "FAIL: property run report not produced"
            exit 1
          fi
          echo "Report produced. Contents:"
          cat "$REPORT" | jq '.results | length' || cat "$REPORT"

          # Verify at least one response_matches_schema failure exists.
          FAILURES=$(jq '[.results[].failures[]? | select(.invariant == "response_matches_schema")] | length' "$REPORT")
          if [ "$FAILURES" -eq 0 ]; then
            echo "FAIL: property testing did not find a response_matches_schema failure"
            exit 1
          fi
          echo "OK: found $FAILURES response_matches_schema failure(s)"

      - name: Verify property violation paths are populated
        run: |
          REPORT="examples/orders-api/bt/.bt/reports/property-run.json"
          EMPTY_PATHS=$(jq '[.results[].failures[]? | select(.invariant == "response_matches_schema" and (.path == null or .path == ""))] | length' "$REPORT")
          if [ "$EMPTY_PATHS" -gt 0 ]; then
            echo "FAIL: $EMPTY_PATHS schema violation(s) have empty path fields"
            exit 1
          fi
          echo "OK: all schema violations have populated path fields"

      - name: Verify property run seed is logged
        run: |
          REPORT="examples/orders-api/bt/.bt/reports/property-run.json"
          ZERO_SEEDS=$(jq '[.results[] | select(.strategy_kind == "property" and (.seed == null or .seed == 0))] | length' "$REPORT")
          if [ "$ZERO_SEEDS" -gt 0 ]; then
            echo "FAIL: $ZERO_SEEDS property result(s) have no seed logged"
            exit 1
          fi
          echo "OK: all property results have seeds logged"

      - name: Upload property run report
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: property-run-report
          path: examples/orders-api/bt/.bt/reports/property-run.json
          retention-days: 7
```

## What this proves

By the end of M4.5 the following is true:

- Property testing finds real bugs automatically — no hand-written assertion is needed for the broken endpoint
- Response schema violations are reported at field level with JSON paths, not just at status-code level
- Every failure carries a seed that makes it exactly reproducible
- Shrinking gives developers a minimal case to investigate, not the raw initial input
- The artifact model from M3 is inherited by property testing with zero extra code
- CI blocks and reports on schema-level regressions, not just HTTP 5xx

## M4.5 exit criterion

`bt run --strategy property` finds the broken endpoint's `response_matches_schema` violation automatically. The CI pipeline:
- Produces a JSON report containing at least one `response_matches_schema` failure with a populated `path` field
- Logs the seed for every property result
- Uploads the report and artifacts as build outputs
- Passes the existing M2.5 and M3.5 steps without regression
