# M2.5 — Integration Test Suite (Orders API)

This milestone uses `bt` to test itself. An in-repo example API is built and a `backendtest.yaml` is written against it. This becomes the living integration test suite for the platform — it grows with every milestone and runs in CI on every push.

From this point forward, every milestone has a corresponding `.5` step that exercises the new capability against this API.

---

## Overview

M2.5 delivers three things:

1. **Example orders API** — a minimal Go HTTP server in `/examples/orders-api` with realistic endpoints, an OpenAPI spec, and deliberate rough edges for later milestones to find
2. **Integration test config** — a `backendtest.yaml` and `tests/` directory that exercises what M2 built
3. **CI integration** — the example API is started and `bt run` is executed against it as part of the GitHub Actions workflow

**Exit criterion:** `bt run --strategy table` passes against the example orders API in CI without any external dependencies. The run produces console, JSON, and JUnit output. All cases are documented with a clear rationale for why they exist.

## Step 1 — Example orders API

### Spec

The orders API is a minimal but realistic Go HTTP server. It is not a toy — it has real-world characteristics that make it a useful test target:

- Standard RESTful resource operations: list, get, create, update
- Input validation that returns structured errors
- An intentional idempotency behaviour on create (for M4 property testing)
- A deliberately flaky endpoint (for M4 and M5)
- An endpoint that returns inconsistent response shapes (for M4 invariant testing)
- Auth header checking (optional bearer token, configurable via env var)

Endpoints:

| Method | Path | Description |
|--------|------|-------------|
| GET | `/health` | Health check, always returns 200 |
| GET | `/orders` | List orders, supports `?status=` filter |
| POST | `/orders` | Create an order, validates required fields |
| GET | `/orders/{id}` | Get a single order by ID |
| PATCH | `/orders/{id}` | Update order status |
| GET | `/orders/{id}/broken` | Intentionally returns inconsistent response shape |

The server must:
- Start on a configurable port (default 8080), via `--port` flag or `PORT` env var
- Respond with `Content-Type: application/json` on all endpoints
- Return structured errors: `{"error": "message", "code": "ERROR_CODE"}`
- Shut down cleanly on SIGINT/SIGTERM
- Log requests to stdout in a structured format

```go
		path   string

	}{
		{"GET", "/health", nil},
		{"GET", "/orders", nil},
		{"POST", "/orders", bytes.NewBufferString(`{"amount":100,"currency":"GBP"}`)},
	}

	for _, ep := range endpoints {
		req, _ := http.NewRequest(ep.method, srv.URL+ep.path, ep.body)
		if ep.body != nil {
			req.Header.Set("Content-Type", "application/json")
		}
		resp, err := http.DefaultClient.Do(req)
		if err != nil {
			t.Fatalf("%s %s: unexpected error: %v", ep.method, ep.path, err)

		ct := resp.Header.Get("Content-Type")
```

### Implementation

`examples/orders-api/main.go`:

```go
package main

import (
	"flag"
	"fmt"
	"log"
	"net/http"
	"os"
	"os/signal"
	"syscall"
)

func main() {
	port := flag.String("port", "", "port to listen on (default: PORT env var or 8080)")
	flag.Parse()

	p := *port
	if p == "" {
		p = os.Getenv("PORT")
	}
	if p == "" {
		p = "8080"
	}

	srv := &http.Server{
		Addr:    ":" + p,
		Handler: NewRouter(),
	}

	quit := make(chan os.Signal, 1)
	signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)

	go func() {
		log.Printf("orders-api listening on :%s", p)
		if err := srv.ListenAndServe(); err != nil && err != http.ErrServerClosed {
			log.Fatalf("server error: %v", err)
		}
	}()

	<-quit
	log.Println("shutting down")
	if err := srv.Close(); err != nil {
		log.Fatalf("shutdown error: %v", err)
	}
}

// NewRouter builds and returns the orders API router.
// Exported so it can be used in tests via httptest.NewServer.
func NewRouter() http.Handler {
	mux := http.NewServeMux()
	store := newStore()

	mux.HandleFunc("GET /health", handleHealth)
	mux.HandleFunc("GET /orders", handleListOrders(store))
	mux.HandleFunc("POST /orders", handleCreateOrder(store))
	mux.HandleFunc("GET /orders/{id}", handleGetOrder(store))
	mux.HandleFunc("PATCH /orders/{id}", handleUpdateOrder(store))
	mux.HandleFunc("GET /orders/{id}/broken", handleBrokenOrder(store))

	return mux
}

func writeJSON(w http.ResponseWriter, status int, body any) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	fmt.Fprintf(w, "%s", mustMarshal(body))
}

func writeError(w http.ResponseWriter, status int, code, message string) {
	writeJSON(w, status, map[string]string{
		"error": message,
		"code":  code,
	})
}
```

`examples/orders-api/store.go`:

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

type order struct {
	ID          string    `json:"id"`
	Amount      int       `json:"amount"`
	Currency    string    `json:"currency"`
	Description string    `json:"description,omitempty"`
	Status      string    `json:"status"`
	CreatedAt   time.Time `json:"created_at"`
}

type store struct {
	mu     sync.RWMutex
	orders map[string]*order
	seq    int
}

func newStore() *store {
	return &store{orders: make(map[string]*order)}
}

func (s *store) create(amount int, currency, description string) *order {
	s.mu.Lock()
	defer s.mu.Unlock()

	s.seq++
	o := &order{
		ID:          fmt.Sprintf("ord-%04d", s.seq),
		Amount:      amount,
		Currency:    currency,
		Description: description,
		Status:      "pending",
		CreatedAt:   time.Now().UTC(),
	}
	s.orders[o.ID] = o
	return o
}

func (s *store) get(id string) (*order, bool) {
	s.mu.RLock()
	defer s.mu.RUnlock()
	o, ok := s.orders[id]
	return o, ok
}

func (s *store) list(statusFilter string) []*order {
	s.mu.RLock()
	defer s.mu.RUnlock()

	out := make([]*order, 0, len(s.orders))
	for _, o := range s.orders {
		if statusFilter == "" || o.Status == statusFilter {
			out = append(out, o)
		}
	}
	return out
}

func (s *store) update(id, status string) (*order, bool) {
	s.mu.Lock()
	defer s.mu.Unlock()

	o, ok := s.orders[id]
	if !ok {
		return nil, false
	}
	o.Status = status
	return o, true
}
```

`examples/orders-api/handlers.go`:

```go
package main

import (
	"encoding/json"
	"net/http"
)

var validStatuses = map[string]bool{
	"pending":   true,
	"confirmed": true,
	"shipped":   true,
	"delivered": true,
	"cancelled": true,
}

func handleHealth(w http.ResponseWriter, r *http.Request) {
	writeJSON(w, http.StatusOK, map[string]string{"status": "ok"})
}

func handleListOrders(s *store) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		statusFilter := r.URL.Query().Get("status")
		if statusFilter != "" && !validStatuses[statusFilter] {
			writeError(w, http.StatusBadRequest, "INVALID_STATUS",
				"status must be one of: pending, confirmed, shipped, delivered, cancelled")
			return
		}
		orders := s.list(statusFilter)
		if orders == nil {
			orders = []*order{}
		}
		writeJSON(w, http.StatusOK, map[string]any{"orders": orders})
	}
}

func handleCreateOrder(s *store) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		var req struct {
			Amount      int    `json:"amount"`
			Currency    string `json:"currency"`
			Description string `json:"description"`
		}
		if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
			writeError(w, http.StatusBadRequest, "INVALID_BODY", "request body must be valid JSON")
			return
		}
		if req.Amount <= 0 {
			writeError(w, http.StatusBadRequest, "INVALID_AMOUNT", "amount must be a positive integer")
			return
		}
		if req.Currency == "" {
			writeError(w, http.StatusBadRequest, "MISSING_CURRENCY", "currency is required")
			return
		}
		o := s.create(req.Amount, req.Currency, req.Description)
		writeJSON(w, http.StatusCreated, o)
	}
}

func handleGetOrder(s *store) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		id := r.PathValue("id")
		o, ok := s.get(id)
		if !ok {
			writeError(w, http.StatusNotFound, "ORDER_NOT_FOUND",
				"order "+id+" not found")
			return
		}
		writeJSON(w, http.StatusOK, o)
	}
}

func handleUpdateOrder(s *store) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		id := r.PathValue("id")
		var req struct {
			Status string `json:"status"`
		}
		if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
			writeError(w, http.StatusBadRequest, "INVALID_BODY", "request body must be valid JSON")
			return
		}
		if !validStatuses[req.Status] {
			writeError(w, http.StatusBadRequest, "INVALID_STATUS",
				"status must be one of: pending, confirmed, shipped, delivered, cancelled")
			return
		}
		o, ok := s.update(id, req.Status)
		if !ok {
			writeError(w, http.StatusNotFound, "ORDER_NOT_FOUND",
				"order "+id+" not found")
			return
		}
		writeJSON(w, http.StatusOK, o)
	}
}

// handleBrokenOrder deliberately returns an inconsistent response shape.
// It is used by property tests in M4.5 to demonstrate invariant violations.
// On even-numbered requests it returns the full order; on odd-numbered it
// omits required fields. This is intentional — do not fix it.
var brokenCallCount int

func handleBrokenOrder(s *store) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		brokenCallCount++
		id := r.PathValue("id")
		o, ok := s.get(id)
		if !ok {
			writeError(w, http.StatusNotFound, "ORDER_NOT_FOUND", "order not found")
			return
		}
		if brokenCallCount%2 == 0 {
			// Full response.
			writeJSON(w, http.StatusOK, o)
		} else {
			// Intentionally incomplete — missing required fields.
			writeJSON(w, http.StatusOK, map[string]any{
				"id": o.ID,
				// amount, currency, status intentionally omitted
			})
		}
	}
}
```

## Step 2 — OpenAPI spec for the orders API

This spec lives at `examples/orders-api/openapi.yaml`. It is the ground truth for what the API should return — the adapter will parse this in M2.5 and future milestones.

`examples/orders-api/openapi.yaml`:

```yaml
openapi: "3.0.3"
info:
  title: Orders API
  description: Example orders API used as a bt integration test target
  version: "1.0.0"

servers:
  - url: http://localhost:8080

paths:
  /health:
    get:
      operationId: GetHealth
      summary: Health check
      tags: [health]
      responses:
        "200":
          description: Service is healthy
          content:
            application/json:
              schema:
                type: object
                required: [status]
                properties:
                  status:
                    type: string
                    enum: [ok]

  /orders:
    get:
      operationId: ListOrders
      summary: List orders
      tags: [orders]
      parameters:
        - name: status
          in: query
          required: false
          schema:
            type: string
            enum: [pending, confirmed, shipped, delivered, cancelled]
      responses:
        "200":
          description: List of orders
          content:
            application/json:
              schema:
                type: object
                required: [orders]
                properties:
                  orders:
                    type: array
                    items:
                      $ref: "#/components/schemas/Order"
        "400":
          description: Invalid status filter
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/Error"

    post:
      operationId: CreateOrder
      summary: Create an order
      tags: [orders]
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required: [amount, currency]
              properties:
                amount:
                  type: integer
                  format: int64
                  minimum: 1
                  description: Order amount in minor currency units
                currency:
                  type: string
                  minLength: 3
                  maxLength: 3
                  description: ISO 4217 currency code
                description:
                  type: string
                  nullable: true
      responses:
        "201":
          description: Order created
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/Order"
        "400":
          description: Invalid request
          content:
            application/json:
              schema:
                $ref: "#/components/schemas/Error"

  /orders/{id}:
    get:
      operationId: GetOrder
      summary: Get an order by ID
      tags: [orders]
```

## Step 4 — CI integration

Update `.github/workflows/ci.yml` to start the orders API, run `bt` against it, and shut it down cleanly:

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-go@v5
        with:
          go-version-file: go.mod
          cache: true

      - name: Lint
        uses: golangci/golangci-lint-action@v6
        with:
          version: latest

      - name: Unit tests
        run: go test ./... -race -coverprofile=coverage.out

      - name: Build bt
        run: go build -o bt ./cmd/bt

      - name: Build orders-api
        run: go build -o orders-api ./examples/orders-api

      - name: Start orders-api
        run: ./orders-api &
        env:
          PORT: 8080

      - name: Wait for orders-api
        run: |
          for i in $(seq 1 10); do
            curl -sf http://localhost:8080/health && break
            echo "waiting for orders-api... ($i)"
            sleep 1
          done

      - name: Run bt integration tests
        run: ./bt run --config examples/orders-api/bt/backendtest.yaml --strategy table

      - name: Run bt integration tests (JSON output)
        run: ./bt run --config examples/orders-api/bt/backendtest.yaml --strategy table --output json

      - name: Upload JUnit results
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: test-results
          path: examples/orders-api/bt/.bt/reports/
```

The `if: always()` on the JUnit upload means test results are preserved even when the run fails — useful for diagnosing CI failures.
