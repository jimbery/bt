# M6.5 — Integration Test Suite (MCP Server)

This milestone exercises M6's MCP server against the in-repo orders API. The proof is end-to-end: a Go test client speaks the MCP protocol over stdio, calls each tool in a realistic sequence, and verifies that structured results match the running API's actual state.

The integration suite now runs five layers in CI: table (M2.5), replay (M3.5), property (M4.5), fuzz (M5.5), and MCP (M6.5).

---

## Overview

M6.5 delivers three things:

1. **A Go MCP test client** — a minimal stdio client in `examples/orders-api/integration/` that exercises the full tool chain: discover → suggest → validate → run → explain
2. **Sequence tests** — verified that calling tools in the documented sequence produces coherent results; the artifact path from `bt_run` is used directly in `bt_explain_failure`
3. **CI integration** — the MCP server is started as a subprocess, tools are exercised, and the CI step fails if any tool returns an error or a malformed response

**Exit criterion:** A Go test client starts `bt mcp serve`, calls all six tools in sequence against the orders API, and receives well-formed responses at every step. The `bt_run` → `bt_explain_failure` chain works end-to-end with real artifact files. All prior CI steps continue to pass.

## Step 1 — MCP test client

### Spec

The test client lives at `internal/mcp/testclient/`. It is a minimal MCP client for testing only — it is not a general-purpose client.

- `Client` starts `bt mcp serve` as a subprocess and communicates over stdio
- `Call(ctx context.Context, tool string, input any) (json.RawMessage, error)` — serialises input, sends a JSON-RPC call to the server, and returns the result
- `Close() error` — sends a graceful shutdown signal and waits for the subprocess to exit
- The client initialises the MCP session (sends the `initialize` message and waits for `initialized`) before any tool call
- If `bt mcp serve` exits unexpectedly, the next `Call` returns an error
- `Client` is not safe for concurrent use — tool calls are sequential

## Step 2 — Tool sequence integration tests

### Spec

The sequence tests live at `examples/orders-api/integration/mcp_test.go` (build tag `integration`). They require the orders API to be running on `localhost:8080` and `bt` to be built and on the path.

The sequence exercised:

1. `bt_discover_operations` → orders API schema → receives operation list
2. `bt_suggest_strategy` → uses the operation list from step 1 → receives recommendations
3. `bt_validate` → orders API `backendtest.yaml` → receives `valid: true`
4. `bt_scaffold_config` → orders API schema → generated YAML passes validation
5. `bt_run` → orders API `backendtest.yaml`, strategy `table` → receives summary with `passed`, `failed`, `total`
6. If `bt_run` produced any failures: `bt_explain_failure` → uses artifact path from step 5 → receives full detail

### Tests

func newMCPClient(t *testing.T) *testclient.Client {
	t.Helper()
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	t.Cleanup(cancel)
	client, err := testclient.Start(ctx, btBinaryPath)
	if err != nil {
		t.Fatalf("failed to start MCP server: %v", err)
	}
	t.Cleanup(func() { client.Close() })
	return client
}

func call(t *testing.T, client *testclient.Client, tool string, input map[string]any) map[string]any {
	t.Helper()
	result, err := client.Call(context.Background(), tool, input)
	if err != nil {
		t.Fatalf("tool %q returned error: %v", tool, err)
	}
	var resp map[string]any
	if err := json.Unmarshal(result, &resp); err != nil {
		t.Fatalf("tool %q returned invalid JSON: %v\nraw: %s", tool, err, result)
	}
	return resp
}

func TestMCPIntegration_SuggestStrategy_ReturnsRecommendationsForAllOperations(t *testing.T) {
	client := newMCPClient(t)

	// First discover operations.
	discoverResp := call(t, client, "bt_discover_operations", map[string]any{
		"schema_path": ordersAPISchemaPath,
	})
	ops := discoverResp["operations"].([]any)

	// Build input for suggest_strategy using the discovered operations.
	opInputs := make([]map[string]any, 0, len(ops))
	for _, op := range ops {
		opMap := op.(map[string]any)
		opInputs = append(opInputs, map[string]any{
			"id":       opMap["id"],
			"method":   opMap["method"],
			"has_body": opMap["has_body"],
		})

	resp := call(t, client, "bt_suggest_strategy", map[string]any{
		"operations": opInputs,
	})

	recs, ok := resp["recommendations"].([]any)
	if !ok {
		t.Fatal("expected recommendations array")
	}
	if len(recs) != len(ops) {
		t.Errorf("expected %d recommendations (one per operation), got %d", len(ops), len(recs))
	}
}

		}
	}
}

		t.Fatal("expected failures array in bt_run response")

		t.Skip("no failures produced — cannot test bt_explain_failure chain")
	}

	// Take the first failure's artifact path and explain it.
	firstFailure := failures[0].(map[string]any)
	artifactPath, ok := firstFailure["artifact_path"].(string)
	if !ok || artifactPath == "" {
		t.Fatal("first failure has no artifact_path")
	}

	explainResp := call(t, client, "bt_explain_failure", map[string]any{
		"artifact_path": artifactPath,
	})

	// Verify the explain response is coherent.
	for _, field := range []string{"case_id", "strategy", "request", "response", "failures", "replay_command"} {
		if _, ok := explainResp[field]; !ok {
			t.Errorf("bt_explain_failure response missing field %q", field)
		}
	}
}

func containsSubstr(s, sub string) bool {
	return len(s) >= len(sub) && (s == sub || func() bool {
		for i := 0; i <= len(s)-len(sub); i++ {
			if s[i:i+len(sub)] == sub {
				return true
			}
		}
		return false
	}())
}

## Step 3 — CI integration

Update `.github/workflows/ci.yml` to add M6.5 steps after M5.5:

```yaml
      # M6.5 — MCP server integration tests
      - name: MCP smoke test — bt_validate via MCP client
        run: |
          # Call bt_validate via a one-shot MCP invocation using bt's built-in
          # JSON output (simpler than driving stdio in bash).
          ./bt validate \
            --config examples/orders-api/bt/backendtest.yaml \
            --output json \
          | jq -e '.valid == true' > /dev/null
          echo "OK: bt_validate reports config is valid"

      - name: MCP smoke test — bt_discover_operations response schema
        run: |
          RESULT=$(./bt mcp call bt_discover_operations \
            --input '{"schema_path":"examples/orders-api/openapi.yaml"}' \
            --output json)
          echo "$RESULT" | jq -e '.operation_count > 0' > /dev/null
          echo "$RESULT" | jq -e '.operations | length > 0' > /dev/null
          echo "$RESULT" | jq -e '.operations[0] | has("id") and has("method") and has("path")' > /dev/null
          echo "OK: bt_discover_operations returned valid operation list"

      - name: MCP smoke test — bt_run response schema
        run: |
          RESULT=$(./bt mcp call bt_run \
            --input '{"config_path":"examples/orders-api/bt/backendtest.yaml","strategy":"table"}' \
            --output json)
          echo "$RESULT" | jq -e 'has("passed") and has("failed") and has("total") and has("strategy") and has("artifact_dir")' > /dev/null
          echo "$RESULT" | jq -e '.passed + .failed + .skipped == .total' > /dev/null
          echo "OK: bt_run response is well-formed"

      - name: MCP smoke test — bt_run then bt_explain_failure chain
        run: |
          # Run expected-failure cases to produce an artifact.
          RUN_RESULT=$(./bt mcp call bt_run \
            --input '{"config_path":"examples/orders-api/bt/backendtest-failures.yaml","strategy":"table"}' \
            --output json) || true

          FAILURE_COUNT=$(echo "$RUN_RESULT" | jq '.failures | length')
          if [ "$FAILURE_COUNT" -eq 0 ]; then
            echo "No failures produced — skipping explain chain"
            exit 0
          fi

          ARTIFACT=$(echo "$RUN_RESULT" | jq -r '.failures[0].artifact_path')
          echo "Explaining artifact: $ARTIFACT"

          EXPLAIN_RESULT=$(./bt mcp call bt_explain_failure \
            --input "{\"artifact_path\":\"$ARTIFACT\"}" \
            --output json)
          echo "$EXPLAIN_RESULT" | jq -e 'has("case_id") and has("request") and has("response") and has("replay_command")' > /dev/null
          echo "$EXPLAIN_RESULT" | jq -e '.replay_command | contains("bt replay")' > /dev/null
          echo "OK: bt_explain_failure returned full failure detail"

      - name: MCP smoke test — bt_scaffold_config produces valid config
        run: |
          SCAFFOLD=$(./bt mcp call bt_scaffold_config \
            --input '{"schema_path":"examples/orders-api/openapi.yaml","base_url":"http://localhost:8080"}' \
            --output json)
          echo "$SCAFFOLD" | jq -e '.config_yaml | length > 0' > /dev/null
          echo "$SCAFFOLD" | jq -r '.config_yaml' > /tmp/scaffolded.yaml

          VALIDATE=$(./bt validate --config /tmp/scaffolded.yaml --output json)
          echo "$VALIDATE" | jq -e '.valid == true' > /dev/null
          echo "OK: scaffolded config passes validation"
```

Note: The above assumes a `bt mcp call <tool> --input <json>` CLI shorthand for single-shot tool invocation without a long-running server. This command should be added to M6 alongside `bt mcp serve`:

- `bt mcp call <tool-name> --input <json>` — starts the MCP server, calls one tool, prints the result as JSON, and exits
- This is primarily for CI and scripting; interactive use uses `bt mcp serve` with a real MCP client
