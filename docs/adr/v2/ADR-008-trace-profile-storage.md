# ADR-008: TraceProfile storage format and location

**Status:** Proposed  
**Date:** 2026-05-12

---

## Context

The trace adapter (M12) produces a `TraceProfile` — a structured description of statistical patterns extracted from a HAR file. This profile must be persisted so that:

- The property strategy can consume it across separate `bt run` invocations without re-parsing the HAR each time
- The stateful strategy (M13) can read sequence data from it to generate flows
- Teams can inspect, diff, and commit the profile to source control if they want reproducible trace-informed test runs
- The `bt` CLI can locate the profile automatically without requiring an explicit flag on every invocation

Two storage options were considered:

**Option A — Separate JSON file in `.bt/trace/profile.json`**  
The profile is a standalone JSON file written to the `.bt/` working directory alongside artifacts. Referenced from `backendtest.yaml` by a `trace.profile` key.

**Option B — Embedded in `backendtest.yaml`**  
The profile is serialised directly into the `backendtest.yaml` config file under a `trace_profile:` top-level key.

---

## Decision

Store the `TraceProfile` as a separate JSON file at `.bt/trace/profile.json`. Reference it from `backendtest.yaml` with a `trace.profile` key that accepts either a relative path (defaulting to `.bt/trace/profile.json`) or an absolute path.

The `TraceProfile` JSON schema is:

```json
{
  "schema_version": "1",
  "generated_at": "<RFC3339 timestamp>",
  "source_har": "<path or filename of the HAR file used>",
  "operations": {
    "<operation_id>": {
      "call_count": 142,
      "frequency_rank": 1,
      "arguments": {
        "<arg_name>": {
          "type": "string | integer | number | boolean",
          "samples": ["GBP", "USD", "EUR"],
          "distribution": {
            "GBP": 0.70,
            "USD": 0.25,
            "EUR": 0.05
          },
          "range": { "min": 10, "max": 500 },
          "null_rate": 0.0,
          "always_present": true
        }
      }
    }
  },
  "sequences": [
    {
      "from_operation_id": "CreateOrder",
      "to_operation_id": "GetOrder",
      "co_occurrence_rate": 0.87,
      "median_gap_ms": 340
    }
  ]
}
```

The `backendtest.yaml` reference:

```yaml
trace:
  profile: .bt/trace/profile.json   # default; omit to use this path automatically
```

---

## Rationale

**Separate file is the right boundary for generated artefacts.** `backendtest.yaml` is the human-authored configuration that teams maintain in source control. The `TraceProfile` is a derived artefact generated by `bt analyze`. Mixing generated data into hand-authored config creates diff noise, makes the config file unwieldy for large profiles (thousands of argument samples), and conflates two separate concerns — what you want to test vs what you observed in traffic.

**`.bt/` is already the working directory for generated state.** Artifact bundles live in `.bt/artifacts/`. The trace profile is the same kind of generated, machine-readable state. Placing it in `.bt/trace/` is consistent with the existing directory convention and makes gitignore rules straightforward (teams can choose to commit or ignore `.bt/trace/` independently of `.bt/artifacts/`).

**JSON is preferable to YAML for a machine-generated file.** The profile is written by `bt analyze` and read by the strategy engine — it is not typically hand-edited. JSON is more compact, has unambiguous parsing semantics, and avoids YAML's whitespace and quoting edge cases. It is also directly inspectable with standard tools (`jq`, `cat`).

**Path reference in `backendtest.yaml` preserves flexibility.** Teams who want to maintain multiple profiles (e.g. production vs staging traffic) can point to different files without changing the analysis pipeline. The default path means zero config for the common case.

**The profile must be versioned.** The `schema_version` field allows the parser to reject or migrate profiles produced by an older `bt` binary. This is a forward-compatibility measure — the profile format will evolve as M13 introduces sequence consumption.

---

## Consequences

- `bt analyze <har-file>` writes `.bt/trace/profile.json` and prints its path on success. If `.bt/trace/` does not exist it is created.
- `.bt/trace/profile.json` is added to the default `.gitignore` written by `bt init`. Teams who want to commit their profile must explicitly un-ignore it.
- The property strategy reads the profile at startup if `trace.profile` is set in config. If the file is absent or unparseable, the strategy logs a warning and falls back to uniform schema-derived generation — it does not fail hard.
- The stateful strategy in M13 treats an absent or unparseable profile as "no sequence data available" and requires hand-authored flows to run.
- `TraceProfile.schema_version` must be checked at parse time. An unknown version returns an error with a clear message: `trace profile was generated by a newer version of bt; upgrade to read it`.
- Tests written for M12 must include a test case for each parse failure mode: missing file, invalid JSON, unknown schema version, missing `operations` key. These tests are written as part of M12.5 before M12 implementation begins.

## Test contract (written before implementation)

The following test cases define the acceptance boundary for this ADR. They are written in M12.5 and must pass before M12 is considered complete.

```go
// pkg/model/trace_test.go

func TestTraceProfileParse(t *testing.T) {
    t.Run("valid profile parses correctly", func(t *testing.T) {
        profile := mustParseProfile(t, "testdata/valid_profile.json")
        assert.Equal(t, "1", profile.SchemaVersion)
        assert.Contains(t, profile.Operations, "CreateOrder")
        op := profile.Operations["CreateOrder"]
        assert.Equal(t, 142, op.CallCount)
        arg := op.Arguments["currency"]
        assert.InDelta(t, 0.70, arg.Distribution["GBP"], 0.001)
        assert.True(t, arg.AlwaysPresent)
    })

    t.Run("missing file returns ErrProfileNotFound", func(t *testing.T) {
        _, err := ParseProfile("/nonexistent/path/profile.json")
        assert.ErrorIs(t, err, ErrProfileNotFound)
    })

    t.Run("invalid JSON returns ErrProfileMalformed", func(t *testing.T) {
        _, err := ParseProfile(writeTempFile(t, []byte("not json")))
        assert.ErrorIs(t, err, ErrProfileMalformed)
    })

    t.Run("unknown schema version returns ErrProfileVersionMismatch", func(t *testing.T) {
        _, err := ParseProfile(writeTempFile(t, []byte(`{"schema_version":"99"}`)))
        assert.ErrorIs(t, err, ErrProfileVersionMismatch)
        assert.Contains(t, err.Error(), "upgrade to read it")
    })

    t.Run("missing operations key returns ErrProfileMalformed", func(t *testing.T) {
        _, err := ParseProfile(writeTempFile(t, []byte(`{"schema_version":"1"}`)))
        assert.ErrorIs(t, err, ErrProfileMalformed)
    })
}

// internal/trace/analyze/analyze_test.go

func TestAnalyzeWritesProfile(t *testing.T) {
    dir := t.TempDir()
    profilePath := filepath.Join(dir, ".bt", "trace", "profile.json")

    err := Analyze(context.Background(), AnalyzeConfig{
        HARPath:     "testdata/orders_sample.har",
        OutputPath:  profilePath,
        ServiceHost: "localhost",
    })
    require.NoError(t, err)

    profile, err := ParseProfile(profilePath)
    require.NoError(t, err)

    t.Run("schema version is set", func(t *testing.T) {
        assert.Equal(t, "1", profile.SchemaVersion)
    })
    t.Run("generated_at is a valid RFC3339 timestamp", func(t *testing.T) {
        _, err := time.Parse(time.RFC3339, profile.GeneratedAt)
        assert.NoError(t, err)
    })
    t.Run("source_har reflects the input file", func(t *testing.T) {
        assert.Equal(t, "orders_sample.har", profile.SourceHAR)
    })
    t.Run("operations are populated from HAR entries", func(t *testing.T) {
        assert.NotEmpty(t, profile.Operations)
    })
    t.Run("output directory is created if absent", func(t *testing.T) {
        assert.DirExists(t, filepath.Dir(profilePath))
    })
}
```
